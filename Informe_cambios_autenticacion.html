Informe de cambios del sistema de autenticación

Proyecto: Universidad - Node.js

Fecha: 7 de septiembre de 2026

Registro de usuarios, inicio de sesión y protección del menú

1. Objetivo

Integrar el formulario de registro con el backend para guardar los datos del usuario, permitir que los usuarios registrados inicien sesión con su correo y contraseña, mostrar su nombre en el menú y bloquear el acceso al menú cuando no exista una sesión válida, conservando los estilos y la estructura visual existente.

2. Estado inicial

  • El registro solo mostraba los datos en consola y no los persistía.
  • El login validaba únicamente el usuario fijo admin con contraseña 1234.
  • Había código JavaScript que guardaba credenciales en localStorage.
  • La vista del menú intentaba protegerse desde el navegador y no desde el servidor.
  • Existía una ruta duplicada de /registro que podía responder antes que la vista real.

3. Cambios realizados

3.1 Persistencia de usuarios

Se creó data/usuarios.json como almacenamiento local del proyecto. El servidor lee los usuarios existentes y guarda los nuevos registros en formato JSON.

Se almacenan los datos solicitados: tipo y número de documento, nombres, apellidos, fecha de nacimiento, correo y contraseña protegida.

3.2 Registro

La ruta POST /registro ahora:

  1. Recibe todos los campos del formulario de tres pasos.
  2. Normaliza el correo a minúsculas y elimina espacios externos.
  3. Verifica que el correo y su confirmación coincidan.
  4. Evita duplicar correo o número de documento.
  5. Genera un nombre visible para el menú.
  6. Protege la contraseña mediante scrypt y una sal aleatoria.
  7. Guarda el usuario y redirige al login.

3.3 Inicio de sesión

La ruta POST /login busca el correo registrado, compara la contraseña con el hash almacenado y, si coincide, crea una sesión en el servidor. La sesión se identifica mediante una cookie HTTPOnly llamada sessionId y redirige a /menu.

3.4 Protección del menú

La ruta GET /menu verifica la sesión antes de renderizar la vista. Si no existe una sesión válida, redirige a /login. Cuando existe sesión, envía a la vista el nombre y correo del usuario.

3.5 Cierre de sesión

Se agregó GET /logout, que elimina la sesión del servidor, invalida la cookie y devuelve al usuario al login.

3.6 Vistas y estilos

Se conservaron los estilos actuales. Se eliminó el guardado de credenciales en localStorage, se quitó el JavaScript duplicado del login y el menú ahora muestra el nombre recibido desde el servidor.

4. Archivos modificados

ArchivoCambio

data/usuarios.jsonNuevo archivo de persistencia de usuarios.

5. Seguridad aplicada

  • Las contraseñas no se guardan en texto plano.
  • La cookie de sesión usa HttpOnly y SameSite=Lax.
  • El acceso al menú se valida en el servidor.
  • Se controlan duplicados de correo y documento.
Nota: El archivo JSON es adecuado para este proyecto académico/local. Para producción se recomienda una base de datos y un almacén de sesiones persistente.

7. Uso

  1. Ejecutar npm.cmd run dev.
  2. Abrir http://localhost:5000/registro.
  3. Completar el formulario y finalizar el registro.
  4. Ingresar al login con el correo y contraseña registrados.
  5. El sistema llevará al menú y mostrará el nombre del usuario.
